# DDInter 2.0

DDInter 2.0 (https://ddinter2.scbdd.com/) is the application's external
source for recorded drug interaction pairs. Dataset terms and attribution
are separate from this project's source code license; review
https://ddinter2.scbdd.com/terms/ before redistribution or other use.

## Supplied files and verified schema

The loader reads `data/raw/ddinter/ddinter_downloads_code_*.csv` by
default. `RAW_DDINTER_DIR` can override that location. All eight supplied
files use the columns `DDInterID_A`, `Drug_A`, `DDInterID_B`, `Drug_B`, and
`Level`. Each row has two drug identifiers and names but no direction
field. The application treats a pair as unordered and supports reverse
lookup; direction semantics are not documented by these CSV columns. The
exports contain no mechanism, description, management, or alternatives,
so ingestion leaves those database fields empty. The files are retained
unchanged.

The loader validates the header and required values. Malformed rows are
counted as rejected. A changed schema or conflicting source levels for the
same source ID pair fails clearly and rolls back the transaction. Repeated
unordered ID pairs with matching levels are counted and skipped. Repeated
ingestion does not duplicate database records. Demo data is never used as
a fallback.

## Source levels

`source_risk` preserves the source's `Level` text. `normalized_risk` maps
`Major`, `Moderate`, and `Minor` to lowercase equivalents; other source
values, including `Unknown`, map to `unknown`. Unknown is treated as
unclassified by the application. Major and Moderate source levels drive
matching labels in the UI; the app does not add treatment or dosing advice.
This project does not infer a more specific clinical meaning from the field.

## Matching and result interpretation

Medication matching uses normalized names (case and whitespace) plus a
small explicit alias list. Unmatched names are reported and are not used
for pair lookups. Pair IDs are stored in canonical numeric database order;
source IDs remain on their corresponding drug rows, and lookups work in
either medication order.

No matching row means only that DDInter has no matching record for the
matched pair(s). It is not proof that the combination is safe. A database
failure is returned as an API error and is not converted into a clean
interaction result. Patient summaries are rendered deterministically from
the verified findings rather than generated by an LLM.

## Limitations

- Name resolution is exact after normalization and the small documented
  alias list. It is not a clinical-grade medication identity service.
- DDInter coverage, correctness, and update frequency are not independently
  assessed by this application.
- The importer does not use synthetic demo data, and interaction queries
  only return rows whose source is `DDInter 2.0`.
